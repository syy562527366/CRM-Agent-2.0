# 商品目录导入（合同汇总表 → 商品管理）

> 目的：把两份合同汇总表里的服务项目整理成 CRM 商品目录，让「商品管理」反映真实在售服务与成交情况，
> 而不是演示用的「AI课 / B端课」。
> 脚本：`scripts/import-products.py`（可重复执行，幂等）。

## 一、数据来源

| 文件 | 工作表 | 行数 | 用途 |
|---|---|---|---|
| `2022-2024 碳启城+碳之邦+曼研院  项目汇总（20241225）(1).xlsx` | `2023-2024合同` | 76 | 2021-2024 历史合同 |
| `2025-2026碳启城项目汇总.xlsx` | `导入文档` | 201 | 2025-2026 合同 |

两表都是「合同订单」导出格式：一行一份合同，但**商品信息是横向展开的多行子表**
（产品名称 / 产品编号 / 规格 / 销售单位 / 数量 / 单价 / 折扣 / 售价 / 售价小计），
同一合同的多个产品行里，合同字段只在第一行填写。

## 二、三条提取规则（踩出来的，改脚本前先读）

1. **表头跨行合并**。表是三层表头：大标题、合同字段行、产品子表头行。
   只看单行必漏——合同字段行没有「产品名称」，子表头行没有「合同编号」。
   脚本按「关键词长度从长到短」跨行匹配，避免「售价」抢走「售价小计」的列。
2. **「单价」列不可靠**。绿证 / 碳交易的「单价」在源表里恒为 `200000`（脏数据），
   真单价在「售价（元）」，已用 `售价小计 ≈ 数量 × 售价` 验证过。所以价格一律取「售价」。
3. **参考价按成交笔数加权取中位数**。不能对去重后的价格集合求中位数：
   20000 元成交 1 笔、6000 元成交 60 笔时，去重算法会算成 10000，加权才是 6000。
   价格区间同理，超过中位数 10 倍的行视为整批打包价或录错，不进区间（明细仍保留可追溯）。

## 三、归并与补号

| 情况 | 处理 |
|---|---|
| 同一服务不同年份用了不同编号（`TQC-01` / `TQC.CBAM` / 无编号「CBAM填报」） | 合并成一条，主编号取最近且成交最多的 `TQC-01`，`note` 里注明 |
| 历史合同只写了服务名、没写产品编号（6 项） | 补号 `TQC-HIS-01`~`05`（含双碳培训、绿色工厂评价、碳管理系统等），`note` 注明来源 |
| 源表没有价格（历史合同未填） | `price = 0`，页面显示「待定价」 |
| 原 4 个演示商品 | **不删，改为下架**。27 条演示订单仍引用它们的 ID，删了订单会指向空记录 |

## 五、页面侧变化

| 位置 | 变化 |
|---|---|
| 列表列 | 商品编号 / 商品名称（下挂牌号·单位）/ 类别 / 参考价 / 成交（单数 + 最近成交）/ 状态 |
| 筛选 | 新增「类别」「状态」，状态默认 **上架**（下架的多为演示数据，避免干扰选品） |
| 详情抽屉 | 增加产品编号、类别、单位、历史价格区间、成交单数、累计数量、成交时间、备注 |
| 新增 / 修改 | 增加类别（6 类下拉）、单位、状态；类别保留列表外的历史值，编辑时不会被清空 |
| 订单页 | 新增订单的商品下拉**只列上架商品**；编辑老订单时若商品已下架，补一个「（已下架）」选项避免表单被清空 |
| AI 助手 | `crm_list_products` 固定只取上架，返回类别 / 单位 / 参考价 / 成交单数 |

## 六、重新导入

```bash
python scripts/import-products.py
```

脚本会重新读取两份 xlsx 并覆盖 `data/products.json`（演示商品保留并标为下架）。
输出末尾会打印每个商品的编号 / 参考价 / 区间 / 单数，以及**没匹配上的明细行**——
如果哪天真出现了新编码，这里会报出来，把它加进 `SPECS` 的别名集合即可。

> 前端读取的是 JSON，改完刷新页面即可生效，不需要重启服务。
