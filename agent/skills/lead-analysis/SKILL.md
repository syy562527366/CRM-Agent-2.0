# 客户线索五问分析

## 何时使用

用户点名**一个**客户 / 线索，要判断值不值得跟、怎么跟。典型说法：
分析一下这个客户 / 看看这条线索 / 张三这个客户怎么样 / 这单为什么没成 / 下一步怎么推进。

**不要**用本技能的场景（直接回答更省事）：
- 只问某个字段：「他电话多少」「预算是多少」
- 要一批客户的清单或排序：「哪些线索该跟」——先用 `crm_search_leads` + `crm_lead_stats` 出清单
- 要业绩统计、订单、商品价格

## 执行步骤

### 第 1 步：定位线索

| 用户给的信息 | 做法 |
|---|---|
| 线索编号（LD-2026-0002） | `crm_get_lead(lead_id=..., remark_chars=400)` |
| 只有姓名 | `crm_search_leads(keyword=姓名)`，命中多条时把「编号 + 姓名 + 负责人 + 状态」列给用户选，**不要自己挑一条**；零条就说没找到 |
| 「我的客户」+ 姓名 | 不要传 `assignee`，服务端会按数据范围自动过滤 |

`remark_chars=400` 是有意调的：备注里常写着客户背景、交付时间要求、决策链，
默认 80 字会被截断，而这些正是第 3、5 问的依据。

### 第 2 步：读沟通记录（本技能的关键动作）

```
crm_get_lead_timeline(lead_id=..., limit=20, content_chars=400)
```

- **必须显式传 `content_chars=400`**。默认只给 100 字，客户说的价格异议、竞品名、
  预算口径经常落在后半句，截断后第 3、4 问只能靠猜。
- 按 `sentAt` 从早到晚读，边读边摘三样东西：客户的原话异议、竞品名、时间 / 预算 / 决策人信息。
- 一条都没有 → `competitors` 给空数组，第 3 问按状态判断，不要编造沟通过程。

### 第 3 步：取当前时间

`get_current_time` 拿今天日期，算出 `lastFollowUpAt` 距今天数 —— `intent` 的判定要用这个数，
不要凭「感觉很久没联系」。

### 第 4 步（可选）：商品参考价

只有需要判断「预算够不够买到意向产品」时才调 `crm_list_products`，
只取 `intentProduct` 对应的那一条，不要整表倒进上下文。

## 意向判定规则（按顺序命中即止）

| 条件 | intent |
|---|---|
| 状态 = 成交 | `high` |
| 状态 = 推荐产品 且 距今 ≤ 7 天 | `high` |
| 状态 = 客户流失 | `low` |
| 状态 ∈ 未接触 / 长期未跟进，或距今 > 30 天 | `low` |
| 预算为空，或预算上限 < 意向产品参考价的 50% | 在上一档基础上下调一档 |
| 其余（有预算、8–30 天内有推进、停在方案反馈或考虑中） | `medium` |

规则之间打架时取**低一档**，并在 `intentBasis` 里说明「因为…所以保守判为中」。

## 输出格式：只输出一个卡片围栏

**整条回复只有下面这一个代码围栏，围栏前后不允许出现任何文字。**
不要写「分析完成」「以下是分析结果」，不要写 Markdown 标题，不要写列表，不要解释字段。

````
```lead-report
{ 完整 JSON }
```
````

### JSON 结构与字段含义

```json
{
  "customer": "顾晓芸",
  "leadId": "LD-2026-0106",
  "assignee": "高兵",
  "status": "客户流失",
  "intent": "low",
  "intentBasis": "状态「客户流失」，最近沟通距今 44 天，累计 8 次沟通，预算 10-20 万元",
  "product": "温室气体报告",
  "budget": "10-20 万元",
  "priceNote": "参考价约 5 万元，落在预算区间内，价格不是主要障碍",
  "loss": {
    "category": "选择了竞品",
    "detail": "客户 9-23 表示总部已统一指定供应商，本次采购未进入比价环节",
    "quote": "我们总部今年统一指定了供应商，你们先放着吧",
    "date": "2026-09-23"
  },
  "competitors": [
    { "name": "中创碳投", "attitude": "negative", "quote": "总部那边用的是中创碳投", "date": "2026-09-23" }
  ],
  "actions": [
    {
      "title": "10 月中旬电话回访",
      "detail": "以「总部框架协议是否覆盖子公司」切入，确认明年是否有独立采购窗口",
      "when": "10 月中旬"
    },
    {
      "title": "寄送新版报价单",
      "detail": "按 15 万档重新出价，附同行业案例，撬动预算松动的可能",
      "when": "本周内"
    }
  ]
}
```

| 字段 | 卡片 | 要求 |
|---|---|---|
| `customer` | ① | 客户姓名，必填 |
| `leadId` `assignee` `status` | ① | 原样取工具返回值 |
| `intent` | ① | **必填**，只能是 `high` / `medium` / `low` |
| `intentBasis` | ① | 判定依据，一句话串起状态 + 距今 N 天 + 沟通 M 次 + 预算，**≤ 60 字** |
| `product` | ② | `intentProduct` 原文；为空写「线索未填意向产品」，推断得来的加「（推断）」 |
| `budget` | ② | 预算区间原文，带单位 |
| `priceNote` | ② | 预算与产品价是否匹配，**≤ 50 字**，可省略 |
| `loss.category` | ③ | **必填**，只能从下面枚举里选一个 |
| `loss.detail` | ③ | 具体情况，**≤ 80 字** |
| `loss.quote` | ③ | 客户原话，**照抄沟通记录，不改写、不翻译**，可省略 |
| `loss.date` | ③ | 原话日期，`YYYY-MM-DD` |
| `competitors[].name` | ④ | 只在沟通记录里出现过的名字 |
| `competitors[].attitude` | ④ | 只能是 `positive` / `neutral` / `negative` / `price_sensitive` |
| `competitors[].quote` `date` | ④ | 出处原话与日期，可省略 |
| `actions[].title` | ⑤ | **必填**，动作本身，≤ 14 字 |
| `actions[].detail` | ⑤ | 怎么做、期望拿到什么信息，**≤ 60 字** |
| `actions[].when` | ⑤ | 时间要求，如「本周内」「10 月中旬」，可省略 |

### `loss.category` 枚举（只能选这 9 个之一）

`价格异议`｜`预算不足`｜`选择了竞品`｜`需求不匹配`｜`跟进不及时`｜`决策链受阻`｜`已成交`｜`无法判断`｜`其他`

- 状态 = 成交 → `已成交`，`detail` 改写为促成因素（谁拍的板、什么打动的、周期多久）。
- 沟通记录不足以判断 → `无法判断`，`detail` 直说「沟通记录不足」，**不要编**。
- 状态 = 客户流失 → 必须能定位到某次沟通，`quote` 尽量给原话。

## 空值与缺失

- 没有竞品 → `"competitors": []`，**不要**放占位对象，也不要写「暂无」。
- 没有建议 → `"actions": []`（正常情况不会出现）。
- 拿不到的字段就**整个省略这个 key**，不要写 `null`、不要写「未知」、不要写空字符串。
  卡片会自己显示「—」。

## JSON 合法性（写错整张报告都出不来）

1. 只用双引号，不要单引号、不要尾逗号、不要注释。
2. 所有字符串一行内写完，不要有换行符。
3. 原话里的引号用中文引号「」，不要用英文双引号，否则会破坏 JSON。
4. 输出前自己数一遍括号是否配对。

## 硬性约束

- 事实全部来自工具返回。没取到的省略该字段，**不编造客户原话、金额、竞品名、日期**。
- 手机号只用脱敏值。
- **不要输出任何 Markdown 正文、表格、标题、总结**——五张卡片就是最终交付物。
- 不要额外加「综合评分」「推荐指数」这类卡片里没有的字段，多写的字段不会被展示。
- 只读不写：不得修改 / 删除线索。用户想改时，提示「可以让我发起修改，会弹审批卡确认」。
