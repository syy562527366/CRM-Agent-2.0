# 产品FAQ问题解答

## 何时使用

用户问的是**公司产品服务本身**的资料型问题：

- 怎么收费 / 多少钱 / 报价多少 / 有没有优惠价
- 适合哪些客户 / 我们这行能不能做 / 什么规模的企业需要
- 交付什么成果 / 要多久 / 能不能加急 / 需要我们配合什么
- 这个服务具体包含什么 / 和另一个产品有什么区别
- 你们有没有 XX 服务 / 公司都有哪些产品
- 采购流程、付款、发票、保密、交付物格式、售后这类通用问题

**不要**用本技能（换工具更准）：

| 用户其实是在问 | 用哪个 |
|---|---|
| 某个客户 / 线索的情况、为什么没成交 | `lead-analysis` 技能 + `crm_*` |
| 本月业绩、订单、周报 | `weekly-report` 技能 + `crm_*_stats` |
| 系统里某笔订单金额、某个产品在库记录 | `crm_search_orders` / `crm_list_products` |

知识库是**静态资料**，不含客户数据和实时成交；`crm_list_products` 才是系统里的在售商品记录。两者口径不一样，不要混着报数。

## 执行步骤

### 第 1 步：拆成「产品 × 维度」

每个产品在知识库里固定有 4 类问答，一条问题一块：

| 维度 | 检索词写法 |
|---|---|
| 服务内容 | `<产品> 服务内容 包含什么` |
| 适用客户 | `<产品> 适用客户 适合哪些企业` |
| 交付与周期 | `<产品> 交付与周期 多久 交付物` |
| 计价方式 | `<产品> 计价方式 怎么收费` |

用户一句话问了好几个方面时（「CBAM 怎么收费、适合谁、多久」），**按维度分别检索**，
不要指望一次 `top_k` 全捞到——一次检索常常只覆盖两三块，剩下的会答成「没有」。

### 第 2 步：调用 kb_search

```
kb_search(query="CBAM 填报 计价方式 怎么收费", top_k=5, doc_type="faq")
```

- `doc_type` 固定传 `"faq"`：知识库里产品 FAQ、产品总览、技能文档混在一起，不加过滤会把技能说明也捞出来。
- 单维度 `top_k=5` 足够；**一次问多个产品**（「绿证和碳交易有什么区别」）时用 `top_k=8`，
  同一产品最多占 2 条，这样两个产品才都进得来。
- 返回结构：`{"ok": true, "hits": [{rank, score, title, section, source, content}]}`。
  `score` 低于 0.55 视为不相关，不要拿它硬答。

### 第 3 步：确认产品名对得上

用户叫法常常不是正式产品名（「零碳工程」「碳盘查」「双碳系统」）。对不上时：

1. 先用用户的**原话**检索一次，看命中哪个产品；
2. 还是没有 → 用类别词检索（碳核算核查 / CBAM 合规 / 咨询评价 / 数字化系统 / 碳资产交易 / 培训）；
3. 仍然没有 → 说「知识库里没有叫「XX」的产品」，再列出**最接近的 2–3 个真实产品**让用户确认，
   **不要**把相近产品当作用户问的那个来答。

### 第 4 步：组织回答

只答用户问到的那几个维度，没问的不要凑数。结构化、分点、能直接转给客户：

```
**<产品名>（<编号>）**

- 怎么收费：按个（按季）计，参考 4,000 ~ 20,000 元 / 个，视产品复杂度与欧盟客户要求
- 适合谁：对欧出口钢铁、铝、水泥、化肥、氢、电力的生产商与贸易商
- 交付与周期：CBAM 季度报告 + 计算底稿 + 申报回执；参考 1–2 周 / 季
- 服务内容：① … ② … ③ …

来源：《产品FAQ-1.0》· CBAM 填报服务
```

- **多个产品对比**时用两列小表，一行一个维度，不要写成两坨段落。
- 结尾可给一句销售向提示（「可以做定制报价」这类），但**不能超出知识库内容**去承诺折扣、账期、免费试用。

## 价格口径（最容易被问，也最容易答错）

1. **计价单位必须带上**：按个 / 按份 / 按张 / 按吨 / 按场 / 按天 / 按项目 / 按季。
   不同口径**不能横向比较**——「绿证 0.3–7.8 元/张」和「碳交易 4–7 元/吨」不是一个东西。
2. **区间价是参考价**，不是承诺价。回答用「参考 X ~ Y 元」，不加「起」「一口价」。
3. 知识库里的 `参考价格：历史合同未记录`、`按份计价` 表示**没有归档单价**，
   直说「这个产品没有归档报价，需按项目评估」，**不要**推算单价、不要拿同类产品价格顶替。
4. 用户问折扣 / 最低价 / 能不能便宜：知识库没有折扣政策，只回参考价 + 「具体以商务报价为准」。

## 知识库里没有的时候

- 检索不到、或 `score` 都不达标：**先换 2–3 组关键词再检索**（同义词、类别词、上游概念），
  确认过再说「知识库里没有这项资料」。
- 说清缺的是**哪一项**（是「没有发票税率」，而不是笼统的「没有资料」），并给出下一步
  （「建议问财务」「需要商务确认后回复」）。
- **绝不编造**：不编产品名、不编价格、不编周期、不编客户案例、不编认证资质。
  知识库只有《产品FAQ-1.0》，里面没有的行业数据、政策条文、竞品对比都不要现编。

## 硬性约束

- 事实只能来自 `kb_search` 返回的 `content` 原文；可以改写语气，不能改数字与承诺口径。
- 引用时不要暴露 `score`、`chunk_id`、`doc_id` 这类内部字段；来源统一写《产品FAQ-1.0》。
- 单次回答控制在 400 字内；用户没要求就只答一个产品，不要把所有产品铺一遍。
- 不写「根据知识库第 3 条」这种编号式引用——用户看不懂，也容易被误认为合同条款。
- 这是**只读**技能：不改 CRM 数据，也不改知识库文件。
